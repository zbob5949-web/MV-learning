【四、app\ 各层职责逐层解释】
----------------------------------------------------------
■ app\main.py  程序启动入口
  预期: 创建 FastAPI 实例、注册路由/中间件/异常处理器,
  类似于 `uvicorn app.main:app` 启动的模块。

■ app\api\  路由层(HTTP 接口定义在这层)
  - routers\users.py  所有 /users 相关接口
    ★ 登录/注册/获取用户信息 等接口将来写在这里(见第五部分)
  - routers\news.py   新闻相关接口(列表/详情等)
  - routers\favorite.py  收藏/取消收藏接口
  - routers\history.py   浏览历史接口
  - endpoints.py      (可选)把各 router 汇总再挂到 app

■ app\core\  核心基础设施(与具体业务无关)
  - config\settings.py       从环境变量/.env 读配置(数据库地址、
    Redis 地址、密钥等), pydantic-settings 实现
  - config\logging_config.py 日志格式/级别配置
  - exception\error_code.py  统一错误码定义(如 10001=参数错)
  - exception\exceptions.py  自定义异常类(如 BizError)
  - exception\handlers.py    把自定义异常转成统一 JSON 响应
  - middleware\access_log.py 记录每个请求的访问日志中间件
  - middleware\cors.py       跨域(CORS)中间件
  - response\models.py       统一响应体结构(如 {code,msg,data})
  - response\utils.py        构造成功/失败响应的工具函数

■ app\models\  ORM 数据表模型(对应数据库表结构)
  users(用户) / news(新闻) / favorite(收藏) / history(历史)
  每个类继承 SQLAlchemy Base, 定义字段与表名。

■ app\schemas\  Pydantic 校验模型(接口进出参)
  与 models\ 一一对应, 但职责不同:
  models = 数据库表, schemas = 请求校验/响应序列化。

■ app\crud\  数据访问层(直接操作数据库)
  把"增删改查"从路由里抽出来: 路由调用 crud, crud 操作 models。
  news_cache.py 负责把新闻数据写进/读出 Redis。

■ app\helper\  业务逻辑层(比 crud 高一层的"服务层")
  auth.py 负责登录时的密码校验与 token 签发/验证;
  其余按业务模块编排 crud + 缓存等完成复杂逻辑。

■ app\db\  连接层
  session.py    创建 SQLAlchemy 引擎/会话(MySQL);
  redis_client.py  创建 Redis 连接池。

■ app\cache\  缓存层
  news.py   新闻热数据缓存策略(如详情/列表先进 Redis)。

■ app\utils\  通用工具
  security.py  密码加密(bcrypt)、token 加解密等。
  (utils 放通用函数, helper 放业务函数, 二者有分工)


【五、重点: Login 路由在这份工程里写在哪个文件?】
----------------------------------------------------------
★ 结论: Project1\app\ 目前全部是 0 字节空文件,
   所以【登录接口还没有在 Project1 里书写】★

按上面的分层设计, 将来实现登录时, 代码应当写在这些文件:
  1. Project1\app\api\routers\users.py    —— 路由层
     书写位置示意:
         @router.post("/login")
         async def login(...): ...
     (登录 = POST /users/login 或 /login, 视 API 设计而定)
  2. Project1\app\schemas\users.py        —— 登录请求/响应模型
     (LoginRequest: username/password, TokenResponse: token)
  3. Project1\app\helper\auth.py          —— 认证逻辑
     (校验用户名密码 -> 用 security 生成 token 返回)
  4. Project1\app\crud\users.py           —— 查用户数据
  5. Project1\app\main.py                 —— 挂载 users 路由
     (app.include_router(users_router))

即: 登录的核心"路由定义"将来应书写在
    Project1\app\api\routers\users.py。
